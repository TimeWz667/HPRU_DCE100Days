# scripts_LLM_gen

Scripts that pick up after the synthetic-population and LLM-survey-generation
steps, and take the DCE data through model fitting and scenario analysis.
Full procedural detail lives in the project's `claude/survey-generation-procedure.md`
and `claude/dce-design.md` docs; this README summarises the rationale and
shows how data and parameters move between the scripts here.

---

## 1. Rationale: LLM-generated survey responses

Round 1 of the DCE (`claude/dce-design.md`) uses LLM-simulated respondents
rather than real fieldwork, following the procedure in
`claude/survey-generation-procedure.md`. The core design principles:

- **Demography is given, not invented.** Each respondent's Age/Sex/Religion
  (and, where used, MaritalStatus/LivingWithChildren/CovidExperience) comes
  from an ONS-derived population table, sampled with a seeded, plain
  statistical procedure — never chosen or generated by an LLM.
- **Answer in character, not by a procedure.** A respondent is never handed
  a utility function, a weighted checklist, or a scoring rule. They answer
  the way that person actually would — from belief, instinct, and
  circumstance — and any quantification (fitting a choice model) happens
  afterwards, externally, never inside the respondent's own reasoning.
- **Each respondent is answered independently.** One respondent = one
  isolated decision, with no shared state, memory, or visibility of any
  other respondent's answers.
- **Everything is seeded and versioned**, so a run can be regenerated or
  audited: the population draw, the ideology assignment, the block
  assignment, and (for a genuine LLM roleplay run) the model/temperature/
  seed per call.
- **Ideology as a first-class input.** `ideology.json` defines five named
  behavioural ideologies (Scientific Rationalism, Libertarianism,
  Communitarianism, Conspiracy Ideation, Institutional Trust and
  Technocratic Governance), each with a core belief, descriptive/injunctive
  norms, and a duration-fatigue narrative, sourced from the literature
  review. 10% of respondents are assigned an ideology; the rest answer from
  personal circumstance alone.

**Honesty note on what was actually run at N=100/2000/replications scale:**
the full procedure calls for one independent LLM call per respondent. At
the scale needed here (2,000 respondents × 10 replications), what was
actually generated is a documented *approximation*: respondents are
classified into a small set of archetypes (their ideology if assigned,
otherwise an age/COVID-history/children-based type), and each
(block, archetype) combination is answered once, by hand, in character —
not by a formula, but also not by 20,000 independent LLM calls. This means
replications (`Results/simulated_respondents_ans_s001..010.csv`) vary only
through the demographic/ideology *sampling* draw, not through genuine
respondent-level answer heterogeneity. This is flagged here so it is not
mistaken for the full Step D procedure when the data is used downstream.

The population and survey-generation scripts themselves (population
sampling, archetype answer keys) are not in this folder — only their CSV
outputs are, under `data/Sims/` and `Results/`. This folder starts from
those outputs onward: fitting choice models and running scenario analysis.

## 2. Script summary

| Script | Purpose |
|---|---|
| `1_synthestic population.R` | Builds the base 2,000-person population (Age, Sex, Religion) from ONS mid-year population estimates and the 2021 Census religion breakdown, sampled proportionally by age×sex×religion. Writes `data/Sims/syn_pop_2000.csv`. |
| `2_fit_dce_stan_models.R` | Recodes the fielded `idefix` design (`Surveys/full_surveys_prepilot_nocross.csv`) and one replication's choices (`Results/simulated_respondents_ans_s*.csv` + `_info_s*.csv`) into the dummy-coded scheme used by every `stan/dce_model_*.stan` file, builds a `stan_data` list per Duration variant, compiles and samples all nine models, and compares them by LOO. |
| `3_utility_exp.R` | Rebuilds Option A's utility function in R from its fitted posterior draws (`out/Dur_a_2000.csv`), converts the draws to JSON, and runs a Monte Carlo experiment comparing utility with vs without vaccine availability for a given situation and respondent (age/sex). |
| `4_scenario_utility_plots.R` | Runs the same population-averaged Monte Carlo idea across three named outbreak scenarios (Timely lockdown / Lockdown failed / Overkill lockdown) and all three fitted Duration variants (Dur_a/Dur_b/Dur_c), producing per-scenario and combined bar charts. |

Both `3_utility_exp.R` and `4_scenario_utility_plots.R` rebuild the fitted
model's linear predictor directly from a `.stan` file's parameter names
(matching dummy-coding and reference categories) rather than re-fitting
anything — the Stan models are the single source of truth for how an
attribute maps to a utility term.

## 4. Duration models — short introduction

The DCE utility function is `U = f(PHM x Vaccine) + f(Duration) + Econ +
Infection + Mortality + Education`. Every Stan model in `stan/` shares the
same PHM x Vaccine (6-category dummy), Econ/Infection/Mortality/Education
(dummy-coded) and Sex/Age-group covariate terms; only the Duration term
`f(Duration)` differs. Full detail and reference-category documentation is
in `stan/duration-variants.md` — summary:

| Variant | Duration term | Captures |
|---|---|---|
| **A** (`dce_model_optionA.stan`) | Dummy-coded, 3/6/9 months | A flat, categorical duration effect (no assumed shape) |
| **B** (`dce_model_optionB.stan`) | Single continuous coefficient on raw months | A constant per-month cost |
| **B-convex** (`dce_model_durB_convex.stan`) | `Duration²` | Fatigue: each extra month hurts more |
| **B-concave** (`dce_model_durB_concave.stan`) | `log(1+Duration)` | Habituation: each extra month hurts less |
| **C** (`dce_model_durC.stan`) | `PHM severity x Duration` | Burden = how strict the measure is, times how long it runs |
| **G** (`dce_model_durG.stan`) | `PHM severity x Duration²` | Severity-weighted, accelerating fatigue - the project's recommended substantive model |
| **D** (`dce_model_durD.stan`) | `Vaccine-not-available x exp(-k x Duration/12)`, k fixed at 0.03/year | Time-preference: a distant vaccine is worth less now |
| **E** (`dce_model_durE.stan`) | `Econ level x Duration` | Economic damage compounding over time |
| **F** (`dce_model_durF.stan`) | Random per-respondent slope on G's term | Individual heterogeneity in fatigue rate |

Only Duration variants **A**, **B**, and **C** have been carried through to
the scenario analysis (`4_scenario_utility_plots.R`) so far; B-convex/
B-concave/D/E/F/G are fitted (`2_fit_dce_stan_models.R`) but not yet used in
a scenario plot.

None of the `.stan` files have been compiled/verified in this environment
(no `stanc`/`cmdstan` available) — treat as unverified until run locally.
