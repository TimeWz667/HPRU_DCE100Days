# README — how this package was built

This folder (`Outputs4Sims/`) is the handoff package from the
`HPRU_DCE100Days` discrete choice experiment (DCE) project to the
simulation project. For the model specification and build instructions,
see `build_guide.md` — that document is self-contained and does not
require this one. This document explains where the parameter files came
from, what the underlying Duration models are, and why three particular
ones were selected.

---

## 1. How the data were extracted

Parameters come from `scripts_LLM_gen/2_fit_dce_stan_models.R` in the DCE
project, which fits nine Duration model variants (Section 2 below) to one
simulated survey replication (`Results/simulated_respondents_ans_s001.csv`
+ the `idefix` design), each producing 2,000 posterior draws
(`out/Dur_*_2000.csv`).

`scripts_LLM_gen/6_parameters_extraction.R` turns three of those draw
files into this package's `Pars_s001.csv` files:

1. Loads `Results/simulated_respondents_info_s001.csv` — the 2,000
   respondents' demographics, survey block, and ideology assignment.
2. For each of the three selected Duration variants, loads that variant's
   2,000 posterior draws (`out/Dur_a_2000.csv`, `out/Dur_d_2000.csv`,
   `out/Dur_f_2000.csv`).
3. Assigns each respondent one posterior draw, **at random, independently,
   with replacement**, using a fixed seed so the pairing is reproducible.
4. Combines each respondent's info with their assigned draw into one row,
   and writes the result as `Scenario_{n}/Pars_s001.csv`.

This supersedes an earlier version of this package
(`5_parameters_extraction.R`), which shipped the raw 2,000-draw array per
Duration variant as JSON, for the simulation to sample from itself at run
time. The current version does that sampling once, up front, and hands
over an already-paired table instead.

**What this trades away:** the respondent-to-draw pairing is now fixed in
the file. `Pars_s001.csv` represents **one realised Monte Carlo pairing**,
not the full posterior available to resample from. If the simulation
needs population-level uncertainty intervals that reflect resampling the
pairing itself (as opposed to stochasticity the simulation itself adds on
top of a fixed pairing), a new file with an independent pairing needs to
be requested from this project — re-running `6_parameters_extraction.R`
with a different seed produces one.

**The `s001` suffix** mirrors the survey-replication numbering used in
`Results/simulated_respondents_info_s*.csv` / `_ans_s*.csv` upstream. Only
`s001` has been fitted and extracted today; if further replications are
fitted, additional files (`Pars_s002.csv`, ...) may appear in the same
`Scenario_{n}/` folders.

## 2. Underlying models

The DCE utility function is:

```
Utility = f(PHM x Vaccine) + f(Duration) + Econ + Infection + Mortality + Education
```

Nine Duration model variants were fitted, differing only in `f(Duration)`
— everything else in the utility function is identical across all of
them. Full detail and reference-category documentation is in
`duration-variants.md`; summary:

| Variant | Duration term | Captures |
|---|---|---|
| **A** | Dummy-coded, 3/6/9 months | A flat, categorical duration effect (no assumed shape) |
| **B** | Single continuous coefficient on raw months | A constant per-month cost |
| **B-convex** | `Duration²` | Fatigue: each extra month hurts more |
| **B-concave** | `log(1+Duration)` | Habituation: each extra month hurts less |
| **C** | `PHM severity x Duration` | Burden = how strict the measure is, times how long it runs |
| **D** | `Vaccine-not-available x exp(-k x Duration/12)`, k = 0.03/year | Time preference: a distant vaccine is worth less now |
| **E** | `Econ level x Duration` | Economic damage compounding over time |
| **F** | Severity x Duration², plus a random per-respondent slope | Individual heterogeneity in fatigue rate |
| **G** | `PHM severity x Duration²` | Severity-weighted, accelerating fatigue |

None of the underlying Stan models have been compiled or verified (no
`stanc`/`cmdstan` toolchain was available in the environment that produced
them) — treat all nine, and hence any posterior draws from them, as
unverified until independently checked. The fitted data underlying every
variant is from one simulated survey replication, itself generated by an
LLM-based approximation rather than real fieldwork (see the DCE project's
`scripts_LLM_gen/README.md` for the fidelity caveats on that step) — these
are synthetic, exploratory parameter estimates, not validated behavioural
coefficients.

A set of directional sanity checks (`scripts_LLM_gen/direction_test_report.md`)
was run across all nine variants before selection — see Section 3. One
finding worth repeating here: `b_econ20`/`b_econ40` (the economic-cost
coefficients) flip sign across the nine variants, which is the least
stable part of the fitted utility function.

## 3. Model selection and reasons

Three variants were selected for this package and relabelled:

| Scenario | Variant | Why it was chosen |
|---|---|---|
| `Scenario_1` | `Dur_a` | Parsimonious categorical baseline. Makes no assumption about the shape of the Duration effect, so it's the safest reference point everything else is judged against. Passed its one applicable direction-test check (lockdown-arm fatigue) at 100% of draws. |
| `Scenario_2` | `Dur_d` | Captures a mechanism none of the other variants touch at all: vaccine-availability time-discounting (a distant vaccine is worth less now). Relevant specifically to scenarios where the vaccine is unavailable rather than delayed by measures. Its own internal mechanism (an exponential discount) is well-behaved (monotonic, bounded). |
| `Scenario_3` | `Dur_f` | The richest fatigue mechanism among the tested variants: passed all applicable direction-test checks cleanly (duration harms lockdown more than low-PHM measures; utility falls with duration under lockdown; low-PHM measures fatigue less than lockdown) at 100% of draws, and additionally supports individual heterogeneity in fatigue rate via its random per-respondent slope — useful if the simulation wants between-individual variation in how fatigue accrues. |

Variants not carried forward: `Dur_c` and `Dur_e` are close substitutes
for `Dur_g`/`Dur_f` (the same PHM-severity-driven fatigue pattern, without
the acceleration or heterogeneity), so keeping them alongside `Dur_f`
would be redundant. `Dur_g` was a strong performer on the direction tests
but was superseded by `Dur_f`, which adds individual heterogeneity on top
of the same severity x Duration² mechanism. `Dur_b`, `Dur_b_convex` and
`Dur_b_concave` showed no mechanism to respond to measure severity at all
in the direction tests, which was the main reason they weren't carried
forward.

This selection was based on directional plausibility (sign checks, not
effect sizes) and documented project intent, not on out-of-sample fit —
LOO model comparison across the nine variants has not been run in this
package's preparation.
